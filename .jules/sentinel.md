## 2024-05-20 - Insecure Deserialization in Firebase Remote Config
**Vulnerability:** The application parsed JSON payloads from `FirebaseRemoteConfig` and immediately casted/mapped the raw dynamic data into model classes (`CustomFormulaData.fromMap`) without validating the root structure (e.g., assuming it's a List) or the individual item structures (e.g., assuming properties like `inputLabels` are Lists). This allows a malformed or manipulated remote payload to trigger unhandled `TypeError` exceptions, leading to an immediate application crash (Client-Side Denial of Service).
**Learning:** Dart's dynamic typing during JSON deserialization is dangerous. `as List<String>` or `List<String>.from()` will throw runtime exceptions if the underlying data is `null`, a `String`, or missing. External data sources like Remote Config must be treated with the same distrust as user input.
**Prevention:** Always validate the root JSON structure first (`if (decoded is! List) return;`). Within model factories, use explicit type checks (`labelsRaw is List`) and safe conversion operators (`?.toString() ?? ''`) to gracefully handle missing or incorrectly typed fields, falling back to safe default values instead of crashing.
