## 2024-05-17 - Prevent TypeError crashes from malformed remote JSON arrays
**Vulnerability:** External payloads (like from Firebase Remote Config or SharedPreferences) were being directly mapped using `List<dynamic>` and `Map<String, dynamic>` typecasts without verifying the structural integrity of the parsed elements. This can lead to fatal unhandled `TypeError` crashes if the remote data is maliciously altered or incorrectly formatted.
**Learning:** Dart's strict type system will throw a runtime `TypeError` when iterating over collections if an element does not match the expected type (e.g., expecting `Map<String, dynamic>` but receiving a `String`). Typecasting alone is insufficient to prevent this.
**Prevention:** Always implement defensive type checking and safe default values when parsing external data. Ensure the parent collection matches the expected type (e.g., `decoded is List`), use `whereType<Map<String, dynamic>>()` to filter out malformed list elements before mapping, and use safe conversion operators like `?.toString() ?? ''` for map values.
